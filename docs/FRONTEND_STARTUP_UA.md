# Початковий екран та діагностика білого екрана

## Зміни

- Статичний індикатор у index.html поза root React: не залежить від запуску основного JavaScript. Кнопка повтору та пояснення з'являються при стартовій помилці або після 15 секунд очікування. Пізній успішний запуск прибирає індикатор.
- ApplicationBoundary охоплює провайдери та React-застосунок: помилка рендеру показує той самий статичний екран. Сесії й паролі автоматично не видаляються.
- jQuery зберігається локально у public/vendor (копія встановленої залежності npm із ліцензійним заголовком); старт більше не залежить від code.jquery.com.
- Google Font завантажується неблокувально; до його появи використовується наявний запасний шрифт.
- .htaccess.template вимагає перевірки актуальності index.html, version.json і portal-startup.js. Відсутні /assets-файли повертають 404 замість React HTML як JavaScript.

## Коди на екрані

| Код | Що відомо |
|---|---|
| STARTUP_TIMEOUT | За 15 секунд не отримано сигнал першого рендеру. Причиною може бути мережа, повільний пристрій або інший стартовий збій; це не точний діагноз. |
| MODULE_LOAD_ERROR | Браузер повідомив про помилку завантаження основного module-скрипта. Перевірити мережу, CSP, кеш та наявність файлів збірки. |
| APP_RENDER_ERROR | React не зміг відобразити дерево застосунку. Потрібна перевірка console, браузера та сховища/сесії. |

Екран не розкриває дані авторизації. Помилки зовнішніх SDK не вважаються автоматично помилкою порталу.

## Чому у різних користувачів по-різному

Кеш файлів і стан вкладки, провайдер/DNS/VPN, блокувальники, доступність сторонніх ресурсів, версія Safari/iOS, вільна пам'ять і доступ до сховища можуть відрізнятися. Тому успішне відкриття на одному пристрої не виключає клієнтського збою на іншому. Причину конкретного випадку дилера за одним скриншотом встановити неможливо; при повторі потрібні код, час, модель пристрою та версія iOS. Обмеження: до отримання HTML чи при блокуванні всього JavaScript/стилів жоден клієнтський екран не гарантує відображення.

## Перевірка

Автоматично перевірені успішний/пізній запуск, таймаут, відсутній модуль, помилка React, ізоляція помилки SDK і неблокувальне підключення шрифту. Production build та ESLint нового компонента успішні.

У браузері перевірено нормальний запуск. У тимчасовій збірці навмисно вказано відсутній основний JS: показано MODULE_LOAD_ERROR з кнопкою повтору. Після відновлення файлу кнопка відкрила форму входу. Робочі файли при тесті помилки не пошкоджувалися. Safari на пристрої конкретного дилера не перевірявся.

Локальна збірка frontend/dist оновлена. Для сервера оновити код і виконати npm run build: нові public-файли й .htaccess потраплять у dist через звичайну збірку. Нових залежностей, параметрів .env та міграцій немає.
