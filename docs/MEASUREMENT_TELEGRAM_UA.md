# Telegram про заявки із замірника

Використано наявну таблицю **CalculationIdempotencyRecords**, колонку **ResponseBody**. Нових таблиць, колонок і міграцій не потрібно. Службовий JSON-блок `_measurement_telegram` містить status, deliveries, contractor_guid та короткий payload повідомлення. Основний Status запису залишається succeeded; успішна відповідь 1С збережена. Службові поля не потрапляють у публічну відповідь API замірника.

## Межі та адресати

- Лише успішні заявки MeasurementOrderViewSet, після підтвердження 1С та збереження запису ідемпотентності. Звичайні заявки порталу без службового маркера не розсилаються.
- Відповідальний менеджер контрагента: GetManagerByContractor та GetTelegramID.
- Копія: 716230412. Якщо це також менеджер — одне повідомлення. Якщо менеджера немає, копія все одно надсилається.
- Текст: джерело «Замірник», дилер, номер заявки, кількість конструкцій, GUID прорахунку, коментар. PDF/фото й ключ інтеграції у Telegram не надсилаються.
- Бот: наявний NOTIFICATION_TELEGRAM_BOT_TOKEN, запасний варіант BOT_TOKEN / TELEGRAM_BOT_TOKEN. Нові параметри .env не потрібні.

## Захист від повторів

Idempotency-Key знаходить той самий запис заявки. Службовий блок створюється один раз під блокуванням рядка. Worker атомарно переводить тільки внутрішній pending у sending до мережевого запиту. Повторні API-запити й задачі не надсилають повідомлення повторно.

Beat раз на хвилину підбирає succeeded-записи, де JSON_VALUE(ResponseBody, '$._measurement_telegram.status') = pending. Інші записи не зачіпаються. При недоступності черги pending залишається в БД.

Внутрішні статуси: pending, sending, sent, partial, failed, uncertain. Результати кожного адресата зберігаються окремо. Таймаут чи обрив після відправки неоднозначний; автоматичного повтору немає. sending/partial не скидати навмання — можливе дублювання вже доставленого повідомлення.

Помилка Telegram не змінює успішний результат створення заявки в 1С. Якщо не вдалося записати службовий блок, помилка логується; повтор успішного measurement-запиту може створити його без повторного створення прорахунку.

## Розгортання

Оновити код і перезапустити Django та Celery worker/beat. Для цієї функції migrate більше не потрібен. Локально зайву міграцію 0028 скасовано, таблицю вилучено після перевірки: записів у ній не було. Якщо попередній варіант уже встановлено в іншому середовищі й містить записи, спершу перенести їхні стани за idempotency_key; не видаляти таблицю з даними без перенесення.

26 тестів пройшли з підміною зовнішніх запитів: адресати, повтори, відмови, незалежність основного status=succeeded, виключення звичайних заявок та приховування внутрішнього стану у відповіді API. Реальне тестове повідомлення не надсилалося. Діагностика Celery: шукати Measurement Telegram; токен у логи не виводиться.
