Прибрано кнопки подання/історії, сторінку історії в меню фінансів, фото та PDF-експорт подань, усі funds-transfers API, модулі пошуку маршрутизацій для цієї форми, звірку з ПКО, модель подань і її фонові Telegram/Celery-завдання. Документацію активної звірки видалено, інструкцію розгортання очищено від створення каталогу її фото.

Оплата замовлень, авансові договори, рахунки, рух коштів і сповіщення замірника збережені. Спільний пошук відповідального менеджера перенесено в records/services/manager_service.py; замірник більше не імпортує видалений модуль подань.

## База даних

Підготовлено payments.0006_remove_funds_transfer_submission: DeleteModel видаляє таблицю payments_fundstransfersubmission разом із даними подань під час застосування міграції. На спільній робочій БД ця міграція в межах локальної зміни НЕ запускалася, щоб не зламати сервер зі старим кодом. Історичні міграції 0001–0005 та два викличні об’єкти сховища у models.py залишені лише для сумісності історії міграцій та встановлення з нуля; активної моделі/API немає.

Під час розгортання узгоджено оновити backend і frontend, перезапустити старі процеси Celery/Beat без видалених завдань та застосувати:

```bash
cd /var/www/html/ordersportal.vstg.com.ua/backend
./venv/bin/python manage.py migrate payments
```

Це крок видалення історичних записів подань. Якщо вони потрібні для архіву, резервну копію БД слід зробити до міграції. Старі фото у private_uploads/funds_transfers автоматично Django не видаляє; у цій зміні фізичні файли не стиралися й через API більше не видаються. Вміст інших private_uploads не зачіпався.
