# API створення заявки із замірника

## Прихована сторінка перевірки

Після розгортання коду та збірки фронтенду відкрийте
`/integration-test/measurement` під адміністратором. У меню посилання немає.
Вкажіть внутрішній ID дилера, кількість конструкцій, оберіть PDF та за потреби фото.
Base64 формується автоматично. JWT-захищений серверний обробник
`/api/integrations/measurement/test/` бере ключ із `.env`; браузер ключ не отримує.
Менеджери та дилери до цього обробника доступу не мають.
Результат показується з HTTP-статусом і GUID. Надсилання створює реальну
заявку у зафіксованій тестовій 1С. Після помилки повтор використовує той самий UUID;
кнопка нової заявки створює новий UUID, тому перед її використанням перевірте 1С.

## Зовнішня інтеграція

`POST https://portal.vstg.com.ua/api/integrations/measurement/orders/`

Створює заявку на прорахунок у 1С через `CreateCalculation`, а не проведений
документ «Замовлення покупця». Звичайний API порталу не змінює свій контракт.

## Налаштування

На етапі тестування для цієї інтеграції адресу 1С зафіксовано в коді:
`http://192.168.50.50/oknastyle_vmm/hs/gp-obmen/`.
Значення `ONE_C_URL` для звичайного створення залишається окремим.
Облікові дані для тестової 1С використовуються з `ONE_C_USER` та
`ONE_C_PASSWORD`; вони повинні мати доступ до цієї публікації.

У `backend/.env` порталу та у серверних налаштуваннях Laravel вкажіть однаковий
новий секрет інтеграції. Не передавайте його у JavaScript браузера.

```dotenv
MEASUREMENT_API_KEY=ЗГЕНЕРОВАНИЙ_СЕКРЕТ
```

Генерація: `python -c "import secrets; print(secrets.token_urlsafe(48))"`.
Якщо секрет не задано, endpoint відхиляє всі запити. Після налаштування
перезапустіть Django-сервіс. Нових залежностей та міграцій ця точка не потребує;
наявна міграція `CalculationIdempotencyRecord` має бути застосована.

## Запит

```http
Content-Type: application/json
X-API-KEY: ЗГЕНЕРОВАНИЙ_СЕКРЕТ
Idempotency-Key: 8eb75462-a26b-43aa-893c-dd2c478763c9
```

```json
{
  "user_id": 78,
  "items_count": 3,
  "order_number": "ZAMIR-125",
  "comment": "Заявка із замірника",
  "file": {
    "fileName": "measurement-125.pdf",
    "fileDataB64": "BASE64_РЕАЛЬНОГО_PDF"
  }
}
```

Обов'язкові: `user_id`, `items_count` (ціле >= 1), `file.fileName` і
`file.fileDataB64`, обидва заголовки авторизації/ідемпотентності.
`order_number` необов'язковий: можна передати `"ZAMIR-125"`, порожній рядок
або взагалі не передавати поле. Без поля в 1С надсилається порожній номер.
`user_id` — саме `[portal_db].[dbo].[User].[ID]`, не GUID і не ID Laravel.
Потрібен активний dealer/customer з непростроченим доступом і заповненим
`UserId1C`. Контрагент 1С береться із `UserId1C`. `contractor_guid` та
`contractor_id` передавати не потрібно; такі перевизначення відхиляються.

Ключ є довіреним серверним ключем для всіх таких користувачів. Laravel повинен
визначати `user_id` із перевіреної прив'язки свого акаунта до порталу,
а не дозволяти користувачеві браузера довільно обирати чужий ID.

PDF до 20 МіБ: перевіряються розширення, Base64 та сигнатура `%PDF-`.
Фото необов'язкові: `photos: [{"fileName": "photo.jpg", "fileDataB64": "..."}]`.
До 10 фото по 10 МіБ; JPG, PNG, WebP, із перевіркою сигнатури та розширення.
Це перевірка формату, не антивірусна перевірка і не повний розбір PDF.

Base64 збільшує обсяг приблизно на третину. Максимальний набір (PDF 20 МіБ
та 10 фото по 10 МіБ) займає близько 160 МіБ плюс JSON. Якщо на проксі
є менший ліміт тіла запиту, налаштуйте для цього endpoint щонайменше 170 МіБ.
Ліміти приймального HTTP-сервера 1С також мають пропускати цей обсяг.

Опційні поля доставки сумісні зі звичайним API:
`delivery_is_pickup`, або `delivery_address_guid` з
`delivery_address_coordinates: {"lat": 48.29, "lng": 25.94}` та
`delivery_address_is_default`, або `client_address`.
Одночасно кілька способів доставки заборонені. Без адреси портал передає в 1С
порожній об'єкт очікуваної структури; `orders: []` формується автоматично.

Кожна нова заявка повинна мати новий UUID у `Idempotency-Key`.
Для повторної відправки тієї самої заявки використовуйте той самий UUID.
Ключі повторів ізольовані за `user_id`. При невизначеному результаті 1С
перевірте наявність заявки; не створюйте новий UUID автоматично.

## Відповідь

```json
{
  "success": true,
  "calculation_guid": "11111111-2222-4333-8444-555555555555",
  "portal_user_id": 78,
  "contractor_guid": "aaaaaaaa-bbbb-4ccc-8ddd-eeeeeeeeeeee"
}
```

Файли Base64 у відповідь не повертаються. HTTP 201 — успішне створення;
400 — некоректні поля/UUID; 401 — неправильний або неналаштований ключ;
403 — недоступний користувач; 409 — конфлікт/стан повторної заявки;
502 — помилка з'єднання з 1С. Перевіряйте також тіло відповіді.
