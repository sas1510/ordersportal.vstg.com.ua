# Завантаження сторінок при відкритті

## Зміни

Активні сторінки в routesConfig.jsx і публічні сторінки App.jsx переведено з синхронних імпортів на React.lazy / import(). Vite формує окремі файли сторінок і спільних залежностей. У збірці 38 окремих динамічних сторінок. NotificationPage також використовується всередині хедера, тому її спільний код залишається у стартовому графі.

У PublicLayout, AdminLayout і DealerLayout додано RouteContent: Suspense огортає тільки Outlet. Хедер залишається доступним, поки сторінка завантажується. Легкий CSS-індикатор враховує prefers-reduced-motion. При помилці завантаження показується повідомлення з кнопкою оновлення; перехід на інший маршрут скидає помилку без примусового перемонтування справних сторінок.

Вилучено п'ять невикористаних статичних імпортів. Маршрути, їхні компоненти, параметри та фільтри доступу ролей залишено без змін. Нові бібліотеки не встановлювалися.

## Вимірювання

Порівняно початковий статичний граф production-збірки, а не сумарний розмір усіх файлів на диску.

| Ресурс | До | Після | Зменшення |
|---|---:|---:|---:|
| Початковий JavaScript | 3 362 521 байт | приблизно 689 115 байт | 79,5% |
| Початковий CSS | 799 472 байт | приблизно 254 268 байт | 68,2% |
| JS gzip, локальне вимірювання | 1 035 641 байт | приблизно 232 754 байт | 77,5% |

Дані після округлено: фінальні імена/розміри можуть на кілька байтів відрізнятися після правок форматування. До стартового графа при переході додається обрана сторінка та її залежності. Важка аналітика все ще має окремий великий модуль: ця зміна переносить його завантаження до відкриття розділу. Менший стартовий JS означає менше початкового завантаження, розбору та виконання коду; фактичний час на старому ноутбуці ще не виміряно. Продуктивність відображення довгого списку замовлень тут не змінювалася.

## Перевірки

- Production build успішний.
- Перевірено manifest: OrdersPage, AdminOrderPage, ProductionStatisticsPage, PaymentsPage, ZamirPage та LoginPage відсутні у початковому статичному графі й завантажуються динамічно.
- Вміст масивів маршрутів та фільтрів ролей порівняно з попередньою версією — ідентичний.
- Новий RouteContent пройшов ESLint.
- У браузері на preview-збірці перевірено вхід, головну сторінку й повернення на вхід без авторизації. Закриті сторінки під усіма ролями вручну не перевірялися.

## Оновлення

Локально frontend/dist зібрано. Для сервера достатньо оновити код і виконати npm run build у frontend; змін залежностей, .env чи міграцій немає. Оновлювати HTML та assets узгоджено. Якщо вкладка відкрилась до оновлення і старий chunk уже відсутній, межа помилок запропонує оновити сторінку. За можливості зберігати старі assets на перехідний період розгортання.

У збірці залишаються попередні попередження про NODE_ENV у .env, analytics.png і великий відкладений chunk аналітики. Вони не означають, що цей великий модуль завантажується на кожній сторінці.


## Виправлення спільних стилів 27.10.2026

Після lazy loading виявлено регресії: глобальні CSS інших сторінок раніше впливали на коментарі, label/radio адреси та інші спільні елементи. Зменшення початкового CSS у таблиці вище стосується першого варіанта, який більше не використовується.

Створено `src/styles/portalSharedStyles.js`: він імпортує всі 89 наявних CSS-модулів у порядку попередньої монолітної збірки. Імпорт підключено першим у main.jsx. Компонентні CSS-імпорти залишені, Vite не завантажує їх повторно як окремі CSS сторінок, якщо вони вже включені у спільний файл.

Порівняно AST готового CSS попередньої збірки та виправленої: усі **10 195** оригінальних правил збігаються разом із порядком і контекстом media/keyframes; відсутніх або змінених правил немає. Додатково залишається тільки новий RouteContent-індикатор.

Стартовий CSS повернувся приблизно до **800 КБ**, щоб зберегти початкове оформлення всіх сторінок. JavaScript залишається розділеним: старт близько **687 КБ** замість 3,36 МБ, сторінки й важка аналітика підвантажуються при відкритті. Подальше розділення CSS потребує спочатку ізолювати глобальні селектори за компонентами, а не просто відкладати файли.

Відновлено попередні глобальні кольори коментарів, зокрема світлий текст у темній темі, та оформлення label/radio для «Моя адреса / Клієнтська адреса / Самовивіз». Для сервера застосування стандартне: оновити код і виконати npm run build у frontend. Локальна збірка оновлена.
