# Звірка поданих коштів із ПКО

У звіті «Історія передавання коштів» кнопка **«Звірити з ПКО»** перевіряє доступні працівнику подання з урахуванням обраного дилера. Автоматична задача Celery Beat запускається щодня щогодини з 09:00 до 18:00 включно за київським часом, до 50 груп за один запуск. Уночі автоматична звірка не запускається. Час останньої перевірки відображається у звіті.

При завантаженні історії (у дилера та у звіті працівника) видимі 20 подань звіряються з ПКО перед поверненням відповіді. Перехід між сторінками також запускає звірку відповідної сторінки. Якщо джерело недоступне, історія відкривається зі збереженими результатами й попередженням. Нічне обмеження стосується лише планових запусків.

## Правила

- Джерело: ПКО з `oknastyle_biV2` через linked server `WST\WST`, як у виборі маршрутизацій.
- Збігаються **GUID маршрутизації**, контрагент і валюта. Номер маршруту відображається для користувача; пошук за GUID виключає збіги однакових номерів.
- Враховуються лише проведені ПКО без позначки видалення, датовані не раніше передачі коштів.
- Порівнюється сума документа ПКО із сумою подання. Декілька ордерів можуть закривати одне подання.
- Якщо подань за одним маршрутом декілька, сума розподіляється за датою передачі, часом подання та ID. Один ПКО не зараховується повністю до кожного подання.
- Перевищення суми та невідповідність валюти потребують ручної перевірки. Розподіл підтверджує суму надходжень за маршрутом, а не індивідуальне призначення кожного подання в 1С.
- Повторна звірка враховує зміну, скасування проведення або видалення ПКО. Помилка доступу до джерела зберігає попередній результат.
- Старі подання без маршрутизації чи дати передачі автоматично підтвердити неможливо. Дані не підставляються припущенням.

Статуси: **Очікує надходження**, **Частково отримано**, **Отримано**, **Розбіжність**. У деталях показано ПКО, його дату, повну суму та суму, зараховану до конкретного подання. Результати звірки включено до PDF.

## Розгортання

1. Застосувати міграцію перед перезапуском застосунку:

   ```bash
   cd /var/www/html/ordersportal.vstg.com.ua/backend
   ./venv/bin/python manage.py migrate payments
   ```

2. Зібрати frontend та перезапустити Django і Celery worker/beat звичайними командами розгортання.
3. Натиснути «Звірити з ПКО» і перевірити час та результат. Обліковому запису SQL порталу потрібне читання зазначених представлень на linked server. Додаткові ключі `.env` не потрібні.

Дані 1С не змінюються. Результат зберігається в `payments_fundstransfersubmission`: `funds_status`, `received_amount`, `funds_checked_at`, `cash_receipts`, `reconciliation_note`.

## API

`POST /api/payments/funds-transfers/reconcile/?contractor=<GUID або __ALL__>` під JWT працівника порталу. Права: admin, manager, region_manager, branch_manager, branches_director; область дилерів така сама, як у звіті.

Відповідь містить `checked`, `received`, `partial`, `pending`, `mismatch`, `errors`, `has_more`. Якщо `has_more=true`, потрібен наступний запуск. Помилка окремих груп повертає 503 з поясненням; успішно звірені групи залишаються збереженими.
